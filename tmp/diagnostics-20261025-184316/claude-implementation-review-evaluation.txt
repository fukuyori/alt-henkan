Claude Code 実装レビューの評価（2026-10-25）

レビュー原文: claude-implementation-review.txt
対象は最初のCtrl修正（通常テスト1649件時点）。この評価後に加えた世代ガードはClaude Codeによる再レビューは行っていない。

採用・対応
1. visible stale Ctrlの誤変換→hidden化→再送信を防げるという結論は、ソースと回帰テストに整合する。
2. ForeignAltGrSequenceの表現を訂正。LLKHF_INJECTEDのみでは管理外にならず、ExtraInfoが自前でないCtrlは通常の管理対象として処理される。InjectedControlRightAltSequenceへ改名し、READMEと検証資料も訂正した。実AltGr配列の受入を意味しない。
3. Consume内のSendInput後に状態を上書きする指摘を調査した。FakePlatform.AfterSendでCtrl upがOSへ反映された後・送信関数が戻る前に非自前Ctrl downを再入させると、左右×OriginalDownPassed/NativeDownSentの4条件で新しい状態がhiddenへ上書きされ、次のupが抑止される。修正前の新規12項目は全失敗（consume-reentry-before.txt）。これは模擬環境での成立証拠であり、実機インシデントの原因確定ではない。
   対応: Consumeで送信前のReleaseAudit.DownVersionを保存し、送信後に新しいdownまたは解放を検出したら、その状態を古い処理で上書きしない。単純なフラグ更新の前倒しは、新しい押下まで保留リピート扱いする可能性があるため選ばなかった。
   12項目が修正後成功（consume-reentry-after.txt）。さらに送信中の非自前upが終えた状態も上書きしない4項目を追加。全1665件成功（implementation-final-tests.txt）。Release build成功・警告0/エラー0（implementation-final-build.txt）。git diff --check成功。

残る制約
- hidden Ctrlでupが欠ける場合は、意図的にWindowsから隠した正常保持と区別する情報が不足する。今回のvisible Ctrl復旧の対象外であり、単純な時間切れやGetAsyncKeyStateだけで解除しない。
- SendInput直後のasync反映順と実機の非自前再入は未確認。模擬イベントは実際のWindowsの配送順を証明しない。
- heldMsは内部Startからの経過であり、押し直した後の物理的な保持時間ではない。
- 0x19残留がフック再登録を阻むことは確認した。PowerToys #6951/#7386に同じVKの残留と回避例があり、詳細はkey19-investigation.txt。名前だけに基づく除外は行っていない。

レビュー文の留保・訂正
- 「監視はキー処理とは別のフック処理スレッド」は不正確。キー処理とWinForms保守タイマーは同じ専用フックスレッドで動く。UIスレッドとは別。再入ガードはその同一スレッドでの処理中を扱う。
- 0x19でRequestRefreshが保留されても「害はありません」という断定は採用しない。フックが失われた場合に自動再登録できない影響が残る。
- 「今回導入された修正必須の不具合なし」はレビュー時点の静的評価。再入仮説は上記の模擬テストで成立を確認し、追加修正したため、そのまま無条件の安全宣言には使わない。
- 最初のCtrl/Alt解放通知欠落と、0x19を残した操作の原因は未特定。PowerToys事例と今回の原因が同一とは断定しない。

実行範囲
- 本体変更はCtrl Consumeの世代ガード、テストと文書の訂正。KeyHoldPolicyは変更していない。
- 今回の追加負荷は、Ctrlを一時解放する経路での整数比較と状態確認のみ。ポーリング追加なし。
- 稼働アプリ操作、実キー合成、インストーラー作成、コミット、タグ、push、Issue更新は行っていない。
